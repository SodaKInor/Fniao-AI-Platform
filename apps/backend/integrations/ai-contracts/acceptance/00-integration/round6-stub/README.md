# 第六轮本地故障、恢复与观测统一验收

00 已按 05 后 06 的顺序合入本地候选，并在隔离的 18100/19100 环境完成 6.5。本文只证明
`remote→stub` 与正式 `disabled` 边界可作为 07 的本地共同起点；不代表 RTX 5070/4090、
真实视频或 RTSP 来源、供应商查询/取消/停止能力已经确认。

## 结论

- 独立 stub 自测 7/7、Java 8 一次性数据库回归 60/60、前端状态机 27/27，前端生产构建与
  后端 `prod,docker-core` 八模块构建通过；两个 OpenSpec 变更严格校验通过。
- 四个测试身份完成真实密码与验证码登录。匿名能力请求为 401，跨用户任务、资产和流会话
  均为 404；供应商错误不清除业务登录。
- 图片、MP4/H.264 边界视频和合成实时流均从业务后端容器经独立 HTTP stub 执行；成果下载
  校验大小和 SHA-256，刷新历史与后端重启后仍可读取。
- 推理 POST 响应丢失只派发一次并进入 `UNKNOWN`；同幂等键重试返回原任务，不透明重发。
  有效空成果保持 `SUCCEEDED`，没有把空结果误写为失败。
- 成果下载中断只重取同一成果三次，不重放推理 POST；失败记录保留供应商检查点并以
  `ARTIFACT_TRANSFER` 终止。
- 重复流事件通过两个各自合法的分页响应返回，后端只入库一条。停止响应丢失只发送一次停止
  POST，会话进入 `UNKNOWN / STOP_CONFIRMATION_UNKNOWN`，再次停止返回 409。
- stub 离线时既有历史和成果仍为 200；队列、在途、阶段耗时、错误和流事件五类 Micrometer
  指标可读，业务与 stub 日志均未出现开发 token 或 RTSP 内容。

## 证据

- `app-e2e.actual.json`：四账号、图片、视频、流、幂等、授权下载、历史与跨用户拒绝。
- `fault-e2e.actual.json`：响应丢失、有效空成果、成果断流、跨页事件去重、停止未知、离线历史、
  指标与后端重启。
- `runtime.actual.json`：镜像摘要、容器健康、迁移校验、数据库行摘要和秘密扫描。
- `docker-image-cleanup.actual.json`：只删除未被容器引用的遗留 WGAI 镜像标签；容器、数据卷和
  构建缓存未删除。

OpenSpec 平台 6.1—6.5 与伴随流 6.1—6.4 据此完成本地模拟门禁。真实服务仍由平台第 9 批和
流第 8 批跟踪，资料到齐后必须重新验证，不能沿用本收据生成真实环境结论。
