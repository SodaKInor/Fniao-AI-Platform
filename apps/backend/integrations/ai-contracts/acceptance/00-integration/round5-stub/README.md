# 第五轮独立 HTTP stub 统一验收

00 在 `a63ae8d` 之后修复应用启动与能力展示缺口，并在隔离的 18100/19100 环境完成
remote→stub 组合验收。本收据只接受本地模拟闭环，不代表 RTX 5070/4090、真实 RTSP 来源、
远程取消或远程停止语义已经确认。

## 结论

- 独立 Node.js stub 自测 5/5、05 fail-closed 门禁 12/12、能力 DTO Java 8 回归 9/9，完整
  `prod,docker-core` 后端构建通过。
- 四个测试身份均通过应用登录；匿名能力请求为 401，跨用户任务、资产和流会话均为 404。
- 图片和 MP4/H.264 边界夹具从真实业务后端经容器网络各派发一次，最终均为 `SUCCEEDED`；
  视频返回带时间偏移的事件与授权截图。
- 合成来源创建实时会话后显示事件和截图；相同幂等键返回原会话，只有 stub 确认后才显示
  `STOPPED`。
- 成果从业务文件接口下载并校验 SHA-256；历史页面保留成功、失败和 `UNKNOWN`，未把诊断期
  的未知结果改写为成功。
- 浏览器显示四个精简入口：图片检测、上传视频分析、实时事件分析和任务历史。视频与流页面、
  详情和历史均显示“模拟”，详情明确提示“未执行真实推理”。

## 本轮发现并修复

- `StreamController` 的 `final` 修饰阻止 Spring CGLIB 代理，已移除并增加代理回归。
- `JobController` 双构造器缺少注入选择，已明确标记应用构造器。
- stub 视频响应曾改写业务 request ID，严格校验因此正确进入 `UNKNOWN`；已改为原样回传并补测试。
- 流 feature gate 曾无条件关闭；现仅在显式 development-stub 且每项能力门禁均确认时开放。
- capability DTO 曾把视频和流都标成 `detection.v1`；现按能力返回三个固定 schema，未知能力
  不再伪装成图片能力。
