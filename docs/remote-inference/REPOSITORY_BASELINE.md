# 仓库基线说明

本次基线保存现有前后端源码、已核对的部署模板、OpenSpec 方案和并行开发约束。它是二次开发的源码起点，不代表远程 GPU 功能已实现，也不代表已完成全新机器恢复演练。

## 保留在本机、不推送的内容

- backend-master 只读参考版。
- 真实 .env、原数据库转储、上传素材、模型权重、运行日志和备份。
- 原项目的环境专用 application 配置、数据库代码生成配置和云服务示例环境配置；其中包含历史连接参数/凭据，不作为新环境可用配置发布。
- 私有/本地安装 JAR、ZIP 与模型运行制品；保留来源/哈希清单，按需要恢复到忽略路径。
- 原 TestMain 演示中的不透明测试令牌；该演示不是核心启动代码。
- 原工作区的 Graphify 输出、Serena 缓存和本机 MCP 配置。

上述排除只影响 Git 跟踪，不删除原工作区文件，也不改动现有 Docker 数据卷或运行服务。既有公开前端签名常量是原代码兼容行为，不作为安全凭据使用；本次远程服务凭据另行管理。

## 新工作区和新机器

1. 先读 deploy/README_DEPLOY.md 和本目录架构/任务说明。现有部署资料是历史起点，涉及原机器绝对路径、固定容器名称和初始化数据时需核对。
2. 从无密钥模板生成本地配置，真实值保留在忽略路径。不要把原环境凭据复制进示例文件。
3. 需要原始数据库结构或私有制品时，按 01-foundation 的来源与恢复说明取得；原始转储不进入公共仓库，新的初始化方式需与真实业务数据分离。
4. 并行测试创建自己的数据库、资产目录、端口与 Compose 覆盖配置。代码 worktree 建立不等于运行环境也已启动。
5. 01-foundation 仍需完成可重建性、数据库/资产备份和入口清单验收。不能仅凭 Git 提交存在就勾选整个第 1 批。

仓库不包含 GitHub 访问令牌。推送只使用临时进程内认证，不把凭据放进 remote URL、提交作者或文件。

推送准备时额外移除了 JwtUtil 与 HelloReceiver1 演示注释中的不透明 JWT 示例，原文件备份保留在忽略的 .setup-backups/github-publish-token-examples/。这不代表已改造认证流程或完成业务回归。
