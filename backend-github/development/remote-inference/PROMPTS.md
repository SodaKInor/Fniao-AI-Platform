# 各轮新对话提示词

这些提示词保留在版本库中；本地快捷入口位于 WGAI-parallel/prompts/。先在对应工作包目录新建对话，核实 code/ 和前置条件，再复制相应提示词。工作包根目录包含 START_HERE.md、AGENTS.md 和 TASKS.md。

## 第一轮：串行准备

先执行 01；其交付集成后再执行 02；最后由 00 冻结共同起点。

### 01-foundation

```text
请接手 01-foundation。先读取 START_HERE.md、AGENTS.md、TASKS.md，并核实当前已有的 Git 仓库、远程地址和 worktree，避免重复初始化。完成本包尚未完成的来源/备份/入口清单与隔离检查，只勾选有证据的子项，交付 HANDOFF.md。不开始算法接入或改业务行为。
```

### 02-contract

```text
请接手 02-contract。核实 01 基线已具备，读取本包说明和架构约束，只完成任务 2.1—2.5：契约、样例、最小公共类型与端口、分层和文件规模检查。同事真实接口未提供时明确标为草案。各公开类型按职责分文件，完成后提交 HANDOFF.md，等待 00 集成冻结，不实现客户端或前端。
```

### 00-integration

```text
请执行第一轮集成。先核实 01、02 的 HANDOFF 和实际提交，检查公开契约、共享类型、架构边界与隔离环境。将通过检查的提交汇入本包集成分支，记录唯一的公共起点提交；让 03、04a、04b 从此起点开始。缺少证据的任务保持未完成，不直接实现三个并行包。
```

## 第二轮：三个包并行开发

以下三段分别用于三个新对话；共同契约提交已集成才开始编码。

### 03-client

```text
请接手 03-client。读取本包说明和 FILE_OWNERSHIP.md，核实当前 code 根、分支以及 00 冻结的公共契约提交。只实现 3.1—3.5 中的后端职责：客户端、配置、协议转换、能力状态、旧执行守卫和权限。Controller、HTTP 适配、配置分别放到对应模块，按规模约束拆文件。用协议夹具验证，不改 04a/04b 或公共 DTO；3.4 的前端部分等待 04b。完成后提交本包代码和 HANDOFF。
```

### 04a-assets-jobs

```text
请接手 04a-assets-jobs。核实与 03、04b 使用同一已集成契约提交。只实现 4.1—4.5 的文件、持久任务、去重、后台等待与成果保存，按 application/domain/port/storage/persistence/api 的职责拆分。使用冻结端口和测试替身，不复制 HTTP 客户端，不改前端或公共契约；数据库迁移只写本包新文件。验证越权、重复派发、UNKNOWN 和文件中断，提交代码与 HANDOFF，不执行 4.7。
```

### 04b-frontend

```text
请接手 04b-frontend。核实公共业务 API 契约提交，读取架构和本包范围。只实现 4.6 及 3.4 的前端入口停用：拆分页面、组件、api/ai 和轮询服务，复用现有 Vue 2 与请求封装。用业务 API 模拟完成上传、状态、成果预览/下载和历史界面，不直接请求 GPU，不修改后端或自行增加接口字段。验证页面离开会停止轮询、旧响应不会覆盖新任务，提交代码与 HANDOFF。
```

## 第三轮：串行合并与完整演示

等待第二轮三个包交付，再由一个集成对话执行。

### 00-integration

```text
请执行第二轮后的串行集成。核实 03、04a、04b 的交付提交、契约版本、文件归属和包内验证；先合入客户端与文件/任务后端，再合入前端。检查层间依赖与大文件职责，解决跨包装配问题，完成任务 4.7 的上传到成果回存、刷新历史和权限验收；核实 3.4 的前后端两部分。只对实际通过的任务更新总表，记录统一验收提交，随后释放 05/06 和 08 的资料准备。
```

## 第四轮：联调、故障验证和发布资料并行

05/06 可做不同文件的工作；08 此轮仅做资料草案，不能正式上线。

### 05-lan

```text
请接手 05-lan，先核实 4.7 已通过。按本包说明完成 5.1—5.4：对齐同事真实接口、访问局域网 Ubuntu 5070 服务、验证实际输入到成果回存及展示。缺少地址/凭据/样例时先整理缺项和配置草案，真实验收保持未完成。与 06 并行时不修改对方的任务/恢复文件；发现实现问题交给所有者或 00 分派，不停止同事服务。提交真实联调证据与 HANDOFF。
```

### 06-resilience

```text
请接手 06-resilience，先核实 4.7 及 04a 的文件交接。实现并验证本地恢复、UNKNOWN、安全重试、取消边界和运行记录，按既定分层拆文件。与 05 并行只改分配文件，通过本地夹具注入故障；真实回归依赖 05 结果，未具备时不勾选整个 6.5。对方无查询/取消时验证准确的不支持行为。交付代码、故障矩阵和 HANDOFF。
```

### 08-release

```text
请执行 08-release 的发布资料准备部分，仅处理 8.1 的独立草案和 8.4 的恢复演练方案。使用本目录 drafts 或独立发布文档，不修改正在由 05 使用的公共配置；不连接正式服务器、不执行迁移/部署、不删除数据、不提前勾选 8.2—8.5。记录需要 07 发布候选和同事正式服务才能执行的事项，交付准备材料与 HANDOFF。
```

## 第五轮：统一回归后串行清理

先执行集成提示词，再执行清理提示词；清理完成后由集成验证发布候选。

### 00-integration

```text
请串行集成 05 与 06 的结果。先检查文件归属和实际交付，核实真实接口及故障语义一致，完成 6.5 的统一回归。任何真实联调未完成、结果未知被误标成功、越权或重复派发问题都保留为未完成并交给对应包处理。通过后记录可供 07 使用的验收提交，不提前删除旧代码。
```

### 07-cleanup

```text
请接手 07-cleanup。只有 05/06 已集成通过且保留/退役清单明确后，才执行 7.1—7.4。按引用清单迁移保留入口、停用绑定、分组清理旧页面和算法依赖；每组验证构建、远程业务及历史成果后提交。不得改 backend-master、同事 GPU 代码或删除历史数据；不得混入 Vue/Java 大版本升级。交付清理对照表和发布候选 HANDOFF。
```

### 00-integration

```text
请核实并合入 07 的清理交付，按既定范围回归登录、远程请求、文件和历史成果。通过后记录正式发布候选的唯一提交/制品版本，交给 08。没有通过的检查保留为未完成，不归档整体变更。
```

## 第六轮：串行正式验收与交付

等待发布候选和正式服务；正式验收之后由 00 汇总整体状态。

### 08-release

```text
请接手 08-release 的正式接入部分。核实 07 发布候选已验收、同事已提供 Ubuntu 单卡 4090 48GB 服务和正式网络条件，按 8.1—8.5 执行业务端发布准备、真实接口验收、隔离备份恢复与兼容回滚。沿用同一业务版本，通过配置切换，不开发 GPU 环境。缺少外部条件时先完成独立准备，真实验收保持未完成；不擅自停止同事服务或重置现用数据。提交正式证据与 HANDOFF。
```

### 00-integration

```text
请核实 08 的正式交付并汇总整个 remote-inference-platform。逐项核对 41 个任务的实际代码、验收和提交记录，区分模拟、局域网和正式环境证据；只有所有必做项完成才同步规格并归档。仍有未完成项时明确列出并保持变更开放，输出最终交付与维护入口。
```
