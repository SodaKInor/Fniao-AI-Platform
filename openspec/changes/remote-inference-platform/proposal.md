## Why

当前管理系统能运行，但识别入口仍依赖 Java 内的旧算法，部分前端页面也缺少目标后端实现。需要把保留业务改为调用同事维护的外部 GPU 服务，由本项目负责请求、成果接收与展示，形成清晰的二次开发边界。

## What Changes

- 保留现有前端和 Java 业务后端，新增统一远程 AI 接入层。浏览器只访问业务后端，后端向同事的服务发送输入并接收成果。
- 首期在同一局域网连接管理机与 Ubuntu RTX 5070 电脑；以后对接 Ubuntu 单张扩容 48GB RTX 4090 服务器，通过部署配置切换地址与凭据。
- 双方约定输入、返回成果、鉴权、超时与错误格式；优先支持普通请求/返回，外部异步查询、去重和取消按同事接口实际能力接入。
- 本项目持久保存调用记录、输入、结果及归属；耗时请求可由业务后端后台执行并向前端返回任务编号，不要求同事重写成异步服务。
- 用业务能力与外部模型标识的映射替代 Java 本地权重路径；维护能力启停和历史结果，GPU 内部模型管理由同事负责。
- **BREAKING**：关闭旧本地模型执行和不需要的匿名测试入口；仅为保留业务提供远程适配，缺后端或淘汰的功能明确停用。
- 建议在现有 WGAI 根目录建立 Git 仓库，保存可运行基线后创建功能改造分支；前后端和接口契约共同版本化。
- 按 8 批交付：版本基线、接口约定、调用基础、模拟完整流程、局域网真实联调、故障与恢复、旧功能迁移清理、正式接入。每批有独立验收记录和版本回退点，具体步骤见 [tasks.md](tasks.md)。
- 支持用户在不同本地目录新建对话并行开发：保留 8 批验收里程碑，划分集成、基线、契约、客户端、文件与任务后端、前端、联调、恢复、清理、正式接入共 10 个工作包。每个代码工作包使用独立 Git worktree 和分支，公共契约冻结后再并行实现。
- 新代码按接口、应用流程、领域规则、外部调用、存储和持久化分层，前端拆分页面、组件、API 和轮询状态；明确文件归属、依赖方向和文件规模约束，禁止将完整功能集中到一个大文件。

## Capabilities

### New Capabilities

- `remote-inference-api`：统一鉴权、外部服务适配、请求/返回转换、可用性和失败提示。
- `inference-assets-jobs`：输入传输、成果回存、调用记录、后台等待、有限恢复和访问权限。
- `model-capability-lifecycle`：管理本项目的业务能力绑定与启停，清理旧入口并保留历史结果。

### Modified Capabilities

无；当前没有已有主规格可修改。

## Impact

- `backend-github`：新增远程调用客户端、接口契约、成果转换和持久化；调整保留业务的调用入口与权限。这里不新增 GPU 服务工程。
- `frontend-vue`：能力入口、执行状态、结果查看下载与旧页面收敛；不向浏览器暴露服务地址或密钥。
- 数据库：增量维护资产、调用记录、业务能力绑定和必要事件；不重跑首次初始化清理 SQL。
- 同事负责：GPU 服务代码、模型、驱动和运行时、服务部署、内部执行与成果生成。双方仅在约定接口和验收样例上协作。
- 部署：本项目维护调用方的开发/正式环境配置；GPU 端部署文件由同事维护。
- 版本管理：本项目统一仓库及改造分支；同事的服务可独立维护仓库，通过接口版本兼容，不要求合并代码历史。
- `backend-master` 继续只读参考。

## Non-goals

本次更新只修订设计，没有创建 Git 仓库/分支或实施代码。后续本项目不负责 GPU 服务开发、算法适配、模型权重、显卡调优和训练平台；不把对方尚未提供的查询/取消/幂等能力当成已实现。持续视频或问答流在双方明确接口后扩展。

前 4 批可先使用明确标注的本地模拟响应，不要求同事服务在线；第 5 批必须使用双方确认的真实接口验收。框架大版本升级另列后续变更，不与本次远程接入同时实施。
