前置：当前工作区。交付：可回溯基线、备份说明、改造分支和入口清单。本批不改变业务行为，不依赖同事接口。全部批次均遵守 [design.md](design.md) 的“每批完成标准”。

- [x] 1.1 复核当前源码、运行配置、原 ZIP / 私有依赖来源，记录管理入口与核心服务状态；交付可追溯的基线清单，不把首页正常当成登录和推理已验收。
- [x] 1.2 准备 Git 忽略规则和无密钥配置/私有制品获取说明；复核候选提交文件不包含真实凭据、原始转储、权重、上传素材、缓存或 backend-master，许可证与来源说明保留。
- [x] 1.3 在现有根目录建立 Git 仓库，保存 main 基线后创建 feature/remote-inference 改造分支；记录基线提交标识，确认工作分支和提交范围正确，不创建重复工程或远程仓库。
- [x] 1.4 制作当前数据库与资产的一致备份并保存在版本库之外，记录恢复步骤及备份对应版本；验证文件可读取、备份清单与校验值齐全，不在现用数据卷上做恢复演练。
- [x] 1.5 根据 audit.md 核对实际路由、菜单和调用点，交付“保留管理 / 迁移执行 / 停用 / 需求待定”清单；逐项记录证据和处置，需求待定项不列入源码或数据删除清单。
- [x] 1.6 按并行工作包清单建立独立 Git worktree / 分支、工作目录登记和运行资源分配；验证各目录的 Git 根路径、分支和写入范围独立，既有端口/数据库/数据卷不被共用，未创建的工作区保持待准备状态。

## 2. 第 2 批：接口契约与模拟样例

前置：第 1 批。交付：本项目可据以开发的契约草案与样例。已有同事接口资料时直接适配；未提供时保留“待双方确认”，真实确认在第 5 批完成。

- [x] 2.1 在 backend-github/integrations/ai-contracts 编写版本化请求/成果契约，列出方法、鉴权、身份字段、输入、输出、错误和限制；验证契约可解析，区分已提供值与待填项，不把示例 URL 当真实地址。
- [x] 2.2 准备一个文件输入、结构化结果及成果文件的最小成功样例，另附有效空成果和错误样例；验证字段、媒体类型与契约一致，所有模拟响应明确标识为测试数据，不冒充实际算法能力。
- [x] 2.3 约定前端业务 API 与外部适配边界、200/202 本地任务语义及 UNKNOWN 含义；核对普通同步接口也能接入，外部查询/取消/去重默认未启用。
- [x] 2.4 形成交接记录模板：开发与正式地址、凭据交付方式、最大输入/时长/并发、成果有效期和可选能力；验证各缺项注明最迟所需批次，开发和正式确认记录分别保留，不要求同事提交 GPU 源码。
- [x] 2.5 按架构约束交付最小共享领域类型、端口接口及请求/成果 DTO，冻结前后端业务契约和 Java 调用边界；验证公共类型不依赖 HTTP/数据库实现，样例符合契约，并交付新增业务文件规模及分层依赖检查，使客户端、文件与任务后端、前端可独立开发。

## 3. 第 3 批：后端调用基础与执行边界

前置：第 2 批草案和样例可用。交付：可通过本地协议夹具验证的调用客户端及基础守卫。本批不需要 GPU 在线。

- [x] 3.1 建立统一客户端边界和 disabled/mock/remote 模式；按第 1 批入口清单检查所有保留的执行入口，验证 remote/disabled 不触发旧 Java 算法，服务离线时不自动回退到旧模型。
- [x] 3.2 实现独立服务凭据、批准地址/可信 CA、连接/处理/传输超时和并发限额配置，提供 backend-github 下的开发/正式模板及部署增量；验证配置有实际消费者，秘密不进入浏览器或普通日志，不新增 GPU 部署工程。
- [x] 3.3 实现请求/错误转换和针对性的协议测试夹具；验证正常响应、有效空成果、连接失败、外部鉴权失败及协议不兼容，GPU 凭据错误不会清除业务用户登录。
- [x] 3.4 收紧旧 AI 匿名执行入口及操作权限，按清单停用缺后端页面的运行入口；验证绕过菜单直接请求仍被拒绝，保留的管理查询正常，新任务不复用旧匿名 WebSocket 传输结果。
- [x] 3.5 实现初版能力可用性接口并区分核心健康与外部可达性；用配置缺失、能力停用、模拟外部离线验证状态反馈，外部无模型就绪信息时不宣称模型已就绪。

## 4. 第 4 批：前后端模拟完整流程

前置：第 2 批公共契约冻结后，文件与任务后端（04a）和前端（04b）可与第 3 批并行实现；第 3 批与两个工作包合并后由集成包（00）验收 4.7。交付：第一个可演示版本，可上传、提交、等待、保存、查看和下载模拟成果。权限与基本故障保护在本批生效。

- [x] 4.1 增量建立资产、调用记录、能力绑定和必要状态事件结构，保存归属及非敏感配置快照；在已有数据库副本验证迁移和重复执行检查，不清空历史数据或重跑初始化清理 SQL。
- [x] 4.2 实现私有资产上传、归属校验和授权下载，以有界内存发送文件/JSON 输入；验证超限输入在外呼前拒绝、跨用户访问被拒绝、旧匿名静态路径不能读取新 AI 私有文件。
- [x] 4.3 实现持久调用 ID、有界后台派发与短等待 200/202；验证受理前已保存记录、请求超过前端等待预算后后台仍等待同一调用，已发送但响应丢失时记录 UNKNOWN 且不自动重发。
- [x] 4.4 实现同用户幂等 key 与规范化请求摘要的本地去重；以重复/并发提交验证同一请求只自动派发一次，同 key 不同输入返回冲突，用户刷新不创建新调用。
- [x] 4.5 实现结构化成果保存和本批契约中使用的文件流/下载引用适配；验证下载地址与重定向受限、长度/校验值可用时核对，文件完整回存后才标记成功，模拟服务离线后历史仍可读。
- [x] 4.6 实现统一前端 API、能力入口、状态查询、错误说明及成果预览下载；用样例验证本批约定类型可展示，页面不暴露 GPU 地址、密钥、权重路径或显卡配置，未支持类型不显示为可用。
- [x] 4.7 通过页面演示“上传 -> 提交 -> 等待 -> 查看/下载 -> 刷新后查看历史”，补充下载中断和权限拒绝验收；记录演示样例、结果与批次版本，明确这是模拟闭环而非真实 GPU 联调。

## 5. 第 5 批：同一局域网真实联调

前置：第 4 批完成，同事提供 Ubuntu RTX 5070 上可调用的服务。交付：首条真实业务的请求和成果验收。若服务尚未就绪，保持本批未完成，可先做第 6 批的本地故障工作。

- [ ] 5.1 对齐并记录双方确认的真实开发契约、首个保留业务、输入/成果样例及接口版本，核定输入限额、超时、并发和成果有效期；核对查询/取消/去重的实际能力，必要时仅调整适配器，不虚构对方支持。
- [ ] 5.2 从管理机实际运行的后端环境访问 GPU 局域网固定地址与端口；验证路由、监听/端口映射和服务鉴权，真实业务素材验证加密通道，不以 ping 成功代替应用请求验收。
- [ ] 5.3 将首个保留业务配置到 remote 模式并完成真实输入发送、成果接收、本地保存及页面查看下载；交付同一 requestId 下的调用和资产记录，确认素材通过网络传送而非使用跨机本地路径。
- [ ] 5.4 按已确认限额验证代表性真实素材和成果格式，记录实际耗时、文件大小、已知服务版本及测试范围；保存开发联调配置模板与回退方式，不把单个样例成功当作所有媒体类型或正式服务器已验收。

## 6. 第 6 批：故障处理与恢复验收

前置：第 4 批数据/任务基础；真实服务相关验收依赖第 5 批。交付：稳定性与错误处理记录。本批可在等待同事接口期间先完成本地可验证部分。

- [ ] 6.1 完善后端重启恢复和安全重试策略：未派发任务可恢复，已派发且无法查询时保留 UNKNOWN，新显式尝试关联原记录；通过不同派发时刻重启验证无盲目重复提交，仅在已确认支持时查询原外部任务。
- [ ] 6.2 实现未派发本地任务取消及契约支持时的远程取消；验证取消与派发竞争、权限、迟到结果和终态保护，无远程取消接口时明确显示不能停止外部处理。
- [ ] 6.3 补充按 requestId 定位的阶段耗时、错误分类、队列/在途数量及必要日志轮转配置；验证外部离线不使核心管理退出服务，日志不包含凭据，限额命中时有可解释反馈。
- [ ] 6.4 用协议夹具覆盖长等待、接收后响应丢失、格式错误、成果过期/下载中断、重复点击和后端重启；逐项记录前端状态、调用次数和文件保存结果，不擅自停止同事服务做故障注入。
- [ ] 6.5 完成登录/越权、真实服务接入和成果历史的跨组件回归，验证服务不可达时已保存成果仍可访问、用户会话不受影响；交付验收矩阵，注明模拟与真实证据，以及不受对方支持的操作。

- [ ] 7.2 实现能力绑定启停及历史快照展示；验证停用阻止新调用，进行中的调用按已确认能力继续处理，旧成果可读且不会触发 GPU 权重/模型删除。
- [ ] 7.3 按引用清单分组清理本项目的过时页面、旧执行代码及无需保留的 native/算法依赖；每组检查保留业务引用和独立构建启动，历史数据和 backend-master 保持完整，分组提交可回退。
